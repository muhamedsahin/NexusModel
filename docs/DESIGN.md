# NexusModel — Computation, made visible

Design direction: a precise computational laboratory with editorial typography, a near-black canvas, cool silver hairlines and one electric chartreuse accent. The light theme is white and graphite with a darker green accent for readable contrast.

The opening composition pairs a very large, tightly set headline with a real WebGL tensor lattice. Floating annotations explain memory layout and computation. The lattice responds gently to the pointer; particles travel through connections. Motion is functional and bounded, with pause controls, visibility-based rendering and reduced-motion support.

Home narrative: introduction → verified CPU metrics → explicit gradient flow → layer families → source-backed performance comparison → executable getting-started example → documentation entry points. No invented adoption statistics or unsourced performance claims.

Documentation uses a three-column reading layout: grouped navigation, a generous article column and an on-page outline. Content includes constructor defaults, shapes, math, gradients, source links, examples and implementation limitations. Both languages share routes and preserve the current article when switching.

Loading: a brief geometric brand reveal, never a fabricated progress percentage. Preferences persist locally. Content remains readable with reduced motion; WebGL failure falls back to a tensor diagram.

Benchmarks use the repository's published results, distinguish forward-only from forward+backward, disclose transfer exclusions, and provide the original report and CSV download. The browser does not pretend to execute C++ or CUDA benchmarks.

The interactive tensor now supports expanding/collapsing its layers and moving signal pulses. The local comparison study uses independent colors for NexusModel, NumPy and PyTorch, reports the measured winner without favoring a library, and exposes per-workload median/p95 with all raw samples downloadable.
